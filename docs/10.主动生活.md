# 10. 主动生活

## 1. 目标

朋友有自己的日常，用户回来时有东西可聊。主动消息来自真实活动和真实想法，不靠随机问候。

## 2. 活动来源

- B 站
- 新闻
- 网页阅读
- 书、音乐
- 之前聊过的话题
- 日程、约定

活动来源存 `settings` 的 `life_sources`。

## 3. 活动循环

1. 选活动：按人格、生活项目、最近对话、时间、精力选。
2. 执行活动：调用真实工具，结果写入 `life_activities`。
3. 记录：`summary`、`observations`、`tool_calls`、`content_depth`。
4. 形成想法：写入 `last_thought`、`open_question`。
5. 生成候选：生活观察、`thoughts`、未结束话题。
6. 判断值不值得分享。
7. 分享后看用户回应。

## 4. 分享标准

必须同时有：

- 具体观察
- 她自己的反应
- 和用户有关的理由

没有就不发。低质量结果只留在 `last_observation`，聊天时再如实说。

## 5. 频率

不设每日次数。参考老版主动消息：

- 随机心跳
- 每个朋友独立概率
- 冷却时间
- 最近有聊天时全体静默
- 一次最多一条主动消息

参数放 `settings`：

- `life_heartbeat_minutes`
- `life_share_chance`
- `life_cooldown_minutes`

## 6. 不回复

- 用户没回，不追同一条。
- 不连续开新话题。
- 连续 3 条以上没回，优先沉默或只说很短的一句。
- 主动消息未读时在朋友栏显示未读角标；打开聊天后清零。

## 7. 设备与调度

同一时间只有一个活动设备，默认电脑。

- `settings.life_owner_device_id` 记录当前活动设备。
- 手机端首期只接收主动分享，不运行活动引擎。
- 生活线通过 yumeCore 的 `life` 模块同步。
- 用户聊天时暂停生活线推进和分享。

## 8. 数据

使用现有表：

- `life_projects`
- `life_activities`
- `friend_life`
- `thoughts`
- `messages`

不新增表。

## 9. 提示词

主动消息生成时带：

- 这次为什么开口
- 用户回没回
- 形态：分享 / 问一句 / 逗一下 / 说自己的状态 / 只打个招呼 / `[沉默]`

最多 3 个短气泡；第一句直接说事，不写成汇报。不想说就只回 `[沉默]`。

## 10. 接口

使用现有生活线接口：

- `GET /friends/{friend_id}/life`
- `GET /friends/{friend_id}/life/projects`
- `GET /friends/{friend_id}/life/activities`
- `POST /friends/{friend_id}/life/pause`
- `POST /friends/{friend_id}/life/resume`

不新增接口。
