# yumeFriend 技术栈

## 1. 总体

- yumeCore：Kotlin Multiplatform，一套代码，编译到桌面 JVM、Android。
- yumeCore 无界面、无业务模块，只提供清单加载、通用读写、事件、同步、授权、发现、模块生命周期。
- yumeCore 不拥有数据；数据归模块，清单声明表、位置和同步范围。
- yumeFriend 电脑：Electron + React + Python。
- yumeFriend 手机：Kotlin + Compose Multiplatform，Android 同一套代码，直接嵌入 yumeCore。
- 电脑 Python 通过本机 HTTP / WebSocket 调 yumeCore。
- yumeCore 由独立的 JVM host 进程提供本机 HTTP / WebSocket，Electron 负责启动。

## 2. 仓库与版本

- yumeCore 独立仓库、独立版本，发布 JVM / Android 多平台制品。
- yumeFriend 电脑端和 Android 放在同一个产品仓库。
- yumeCore 和 yumeFriend 两个仓库都开源。
- 产品仓库目录：`desktop/`、`android/`、`docs/`。
- 产品源码布局：

```text
desktop/
  src/          React
  electron/     Electron main / preload
  backend/      Python FastAPI
  modules/      模块清单
  scripts/      构建脚本
  resources/    本机运行时制品
android/        Kotlin + Compose
docs/
```

- yumeCore 仓库根目录为 Gradle 工程，源码分 `commonMain`、`jvmMain`、`androidMain`；JVM host 位于 `jvmMain`。
- 初始版本：yumeFriend `0.1.0`，yumeCore `0.2.0`，协议版本 `1`。
- 代码许可证沿用旧版开源决定：Apache-2.0。
- 产品按版本引入，不修改 yumeCore 源码。
- 语义化版本；生态协议版本单独维护。

## 3. yumeCore

| 项目       | 选择                                                     |
| ---------- | -------------------------------------------------------- |
| 语言       | Kotlin Multiplatform                                     |
| 目标       | 桌面 JVM / Android                                       |
| 职责       | 清单加载、通用读写、事件、同步、授权、发现、模块生命周期 |
| 数据       | 不拥有数据；按模块清单读写模块声明的数据                 |
| 数据库适配 | yumeFriend 用 SQLite；其他产品可提供自己的数据库适配器   |
| 同步       | 局域网直连 + 服务器同步，同一套协议                      |
| 界面       | 无                                                       |

不同产品数据库可以不同。同步走逻辑数据，不传数据库文件。

## 6. 手机端

| 项目 | 选择                                           |
| ---- | ---------------------------------------------- |
| 语言 | Kotlin                                         |
| 界面 | Compose Multiplatform                          |
| 核心 | 嵌入同一套 yumeCore                            |
| 数据 | 按模块清单读写本地数据                         |
| 语音 | Android 系统 TTS / STT；云端走同一适配器 |
| 通知 | AlarmManager + 系统通知 |
| 文档抽取 | PDFBox-Android + docx 压缩包 XML |
| 附件 | 本机 `files/assets/` + `index.json`，按 SHA-256 去重 |
| 沉浸 | Compose 全屏 + 立绘 / Live2D；WebView + pixi.js + pixi-live2d-display |
| 局域网同步 | JmDNS + Ktor（电脑）/ NanoHTTPD（Android） |
| 打包 | Android：Gradle / APK |

Android 通过 Gradle composite build 引入独立 yumeCore 仓库；本机默认 `../../yumeCore`，CI 将 yumeCore 检出到 `../yumeCore-src` 并通过 `-PyumeCoreDir` 指定。模块清单复用 `desktop/modules/`。

Android 内置 YUI 立绘和 Live2D 模型文件；Live2D Core 由用户在设置页阅读官方协议后下载到 `files/live2d/live2dcubismcore.min.js`，不打进 APK。

同步依赖：JmDNS 负责 mDNS 发现；Android peer 服务使用 NanoHTTPD；电脑端 peer/server 服务复用 yumeCore JVM host 的 Ktor。

## 7. 通信

本机 HTTP + SSE + WebSocket + JSON。

- 电脑：React → Python 业务；Python → yumeCore。
- 手机：Compose → yumeCore。

## 8. 同步

- 任意两个有 yumeCore 的设备可局域网直连同步。
- 服务器模式可选，用于跨网络和多设备。
- 同步按模块清单交换逻辑数据、事件和附件。
- 服务器只做同步和附件存储，不跑模型、不跑语音。
- 不同数据库的产品通过各自适配器映射到同一份逻辑数据。

## 9. 文件

- 本地文件区存图片、语音、模型；数据库只存路径和元数据。
- 附件按 SHA-256 去重和传输。
- 语音只存本机，按天数或总量清理；旧语音需要时重新合成。
