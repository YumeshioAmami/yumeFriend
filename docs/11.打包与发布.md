# 11. 打包与发布

## 1. 版本

- 应用版本、yumeCore 版本、协议版本分开。
- 应用和 yumeCore 用语义化版本，协议版本用整数。

## 2. 运行

- 电脑启动顺序：Electron → yumeCore → Python → React。
- 开发启动：根目录 `start.cmd` 调用 `scripts/start.ps1`，检查依赖、构建 yumeCore host 和前端后启动 Electron。
- yumeCore 检查数据库并执行迁移。
- 迁移前备份到 `user_data/backups/`。
- 数据库、日志、媒体统一放 `user_data/`。
- Android 直接嵌入 yumeCore，启动时检查数据库并执行迁移。

## 3. yumeCore 发布

- 独立仓库、独立版本、独立标签。
- 发布 JVM / Android 制品。
- 产品固定版本引入。

## 4. 电脑端打包

- 前端：Vite 构建。
- Python：PyInstaller。
- yumeCore：Gradle 构建 JVM 制品。
- 安装包：electron-builder + NSIS。
- 安装时让用户选择目录，`user_data` 放在安装目录旁。
- 安装包包含 Electron / React / Python / yumeCore。
- 自动更新：electron-updater + `latest.yml`。

## 5. Android 打包

- Kotlin + Compose Multiplatform。
- Gradle 输出 APK。
- yumeCore 直接嵌入。
- 自有更新清单 `latest.json` + APK 下载。
- 数据保存在应用本地目录。
- 初始 `versionCode` 为 9，接续老版 7.4.0 的 8，保证同包名覆盖安装。

首次启动检测老版数据库（`messages.mode_at_send` 旧字段）。检测到后先备份到 `files/backups/`，把旧库改名为 `yumefriend.legacy.db`，新库迁移朋友、状态、消息、记忆与事件、文档与切片、日程与事件、想法、音色和聊天模型配置。旧版图片、语音文件不迁移。

`latest.json` 字段：

```json
{
  "version_code": 2,
  "version_name": "0.1.1",
  "download_url": "https://example.com/yumefriend.apk",
  "notes": "更新说明"
}
```

设置页保存 `apk_update_url`；`version_code` 高于当前安装包时下载到应用文件目录，再交给系统安装器。

## 6. 服务器

- 原生部署。
- systemd 管理 yumeCore 服务进程。
- 数据目录放 `/srv/yumefriend/data`。
- token 用环境变量配置。
- 前面放 Nginx / Caddy 做 HTTPS。
- 服务器负责同步和附件存储。
- 局域网同步继续保留。

## 7. CI

- GitHub Actions。
- 前端：在 `desktop` 执行 oxlint + Vitest + Playwright。
- Python：在 `desktop/backend` 执行 ruff + pytest。
- Kotlin：在 `android` 执行 Gradle + Kotlin Test。
- 打标签触发正式构建。
