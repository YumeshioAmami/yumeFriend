# yumeFriend 数据模型

## 1. 总则

- 单用户，没有 `user_id`。
- 每台设备一个 SQLite 数据库；服务器模式只做同步和附件仓库。
- 本文件是 yumeFriend 的 SQLite 数据模型；其他产品可以使用不同数据库，通过 yumeCore 适配器映射成同一份逻辑数据。
- 每个朋友一条连续会话，不建 `conversations` 表。
- 主键使用 UUID 字符串。
- 时间统一使用 UTC ISO8601；日程的日期和时间使用本地值。
- 普通主表公共字段：`id`、`created_at`、`updated_at`、`deleted_at`、`origin_device_id`、`origin_product_id`。
- 只追加表公共字段：`id`、`created_at`、`origin_device_id`、`origin_product_id`。
- 所有媒体统一放入 `assets`，数据库只存文件信息和引用关系。

### 1.1 模块 ID

同步和授权使用 `module_id`。具体模块清单由模块清单文件定义，当前约定：

| module_id | 表 |
|---|---|
| `friend` | `friends`、`friend_states` |
| `chat` | `messages`、`message_assets` |
| `memory` | `memories`、`memory_events` |
| `document` | `documents`、`document_chunks` |
| `schedule` | `schedules`、`schedule_events` |
| `thought` | `thoughts` |
| `expression` | `expression_samples`、`style_profiles`、`style_events` |
| `life` | `life_projects`、`life_activities`、`friend_life` |
| `visual` | `visual_packs` |
| `settings` | `settings` |
| `event` | `events` |
| `search` | 无表，联网搜索工具模块 |
| `screen` | 无表，手动截屏工具模块 |
| `file` | 无表，受控文件工具模块 |
| `image` | 无表，图片理解与生成工具模块 |
| `voice` | `voices`（仅本机，不参与同步） |

`assets` 走附件通道；`voices`、`embeddings`、`module_registry` 只存本机，不参与模块同步。

## 4. 归属规则

- `friends` 是最上层，下面是状态、消息、记忆、日程、想法、表达、文档、生活线。
- 消息下面挂附件。
- 文档下面挂切片。
- 生活项目下面挂活动。
- `assets` 是公共文件，头像、消息、文档、立绘都引用它。

## 5. 删除规则

- 删朋友：连带删状态、消息、记忆、日程、想法、表达、文档、生活线，以及附件关系、切片、向量。
- 删消息：只删附件关系；文件没人用了才删。
- 删记忆：记忆没了，改动留痕还在；向量一起删。
- 删文档：连带删切片和向量。
- 删日程：日程没了，改动留痕还在；删朋友时才一起清。
- 删生活项目：活动保留，项目关联置空。
- 删语音文件：消息保留，标成语音缺失，需要时重新合成。
- 删除先打标记，通过删除记录同步到其他设备，之后物理清理。

## 6. 同步

- 同步按模块清单执行，不传数据库文件。
- 支持局域网直连和服务器同步，使用同一套协议。
- 只同步模块声明的数据、事件和附件。
- 删除记录、待同步改动和冲突记录都带 `module_id`。
- 不同数据库的产品通过各自适配器映射到同一份逻辑数据。
- 服务器只做同步和附件存储，不跑模型、不跑语音。

## 7. 索引

- `schedules(date_local, time_local)`，只索引待办
- `document_chunks(document_id, seq)` 唯一
- `embeddings(owner_type, owner_id, model)` 唯一
- `events(created_at)`
- `sync_tombstones(module_id, entity_type, entity_id)` 唯一
- `assets(sha256)` 唯一
- `message_assets(message_id)`
- `grants(peer_id, module_id)`
