# 14. 生态协作协议

版本：1.0
`protocol_version`：1

## 1. 范围

规定 yumeCore 之间、同系列产品之间、设备与同步服务器之间的协作方式：发现、配对、模块清单、授权、事件、能力调用、数据与附件同步。

数据模型以 `5.数据模型` 为准，接口前缀以 `6.接口文档` 为准。

## 2. 标识与版本

- 应用版本、yumeCore 版本用语义化版本，与协议版本分开。
- `product_id`：产品稳定标识。
- `device_id`：设备 UUID。
- `peer_id`：已配对对端记录的 UUID。
- `module_id`：见 `5.数据模型` 的 `1.1 模块 ID`。
- 只接受相同 `protocol_version`。

## 3. 发现与配对

局域网发现：

- mDNS 服务：`_yumecore._tcp.local`
- TXT 字段：`product_id`、`device_id`、`protocol_version`、`core_version`
- 发现结果只表示“看见”，不代表已信任。

配对请求：

```json
POST /peer/v1/pair/request
{
  "product_id": "yumeFriend",
  "device_id": "uuid",
  "protocol_version": 1
}
```

- 用户在对端确认后才建立 peer。
- 配对目标在同步设置中开启“允许其他设备配对”后，配对请求才可建立 peer。
- 对端返回 `peer_id` 和 `pair_secret`。
- 双方保存同一条 peer 记录和 `pair_secret`。
- 后续对端请求带 `X-YF-Peer-Token: {pair_secret}`。
- 服务器同步使用 `X-YF-Server-Token`。

## 4. 模块清单

`GET /modules` 返回模块清单。yumeCore 只加载和校验，不解释业务。

```json
{
  "module_id": "chat",
  "version": "1.0.0",
  "entities": [
    {
      "name": "messages",
      "key": ["id"],
      "sync": true,
      "assets": false,
      "columns": {
        "id": "TEXT",
        "friend_id": "TEXT",
        "role": "TEXT",
        "kind": "TEXT",
        "content": "TEXT",
        "proactive": "INTEGER",
        "status": "TEXT",
        "error_text": "TEXT",
        "mood": "TEXT",
        "segments_json": "TEXT",
        "sources_json": "TEXT",
        "tool_calls_json": "TEXT",
        "voice_status": "TEXT",
        "voice_error": "TEXT",
        "read_at": "TEXT",
        "created_at": "TEXT",
        "updated_at": "TEXT",
        "deleted_at": "TEXT",
        "origin_device_id": "TEXT",
        "origin_product_id": "TEXT"
      }
    },
    {
      "name": "message_assets",
      "key": ["message_id", "role", "position"],
      "sync": true,
      "assets": true,
      "columns": {
        "message_id": "TEXT",
        "asset_id": "TEXT",
        "role": "TEXT",
        "position": "INTEGER",
        "meta_json": "TEXT",
        "created_at": "TEXT",
        "deleted_at": "TEXT"
      }
    }
  ],
  "migrations": [
    {
      "version": 1,
      "sql": [
        "CREATE TABLE messages (id TEXT PRIMARY KEY, friend_id TEXT NOT NULL, role TEXT NOT NULL, kind TEXT NOT NULL, content TEXT NOT NULL, proactive INTEGER NOT NULL, status TEXT NOT NULL, error_text TEXT, mood TEXT, segments_json TEXT, sources_json TEXT, tool_calls_json TEXT, voice_status TEXT, voice_error TEXT, read_at TEXT, created_at TEXT NOT NULL, updated_at TEXT NOT NULL, deleted_at TEXT, origin_device_id TEXT NOT NULL, origin_product_id TEXT NOT NULL);",
        "CREATE TABLE message_assets (message_id TEXT NOT NULL, asset_id TEXT NOT NULL, role TEXT NOT NULL, position INTEGER NOT NULL, meta_json TEXT, created_at TEXT NOT NULL, PRIMARY KEY (message_id, role, position));"
      ]
    },
    {
      "version": 2,
      "sql": [
        "ALTER TABLE message_assets ADD COLUMN deleted_at TEXT;"
      ]
    }
  ],
  "capabilities": [
    {
      "name": "chat.send",
      "input": "ChatSendRequest",
      "output": "ChatSendResult"
    }
  ],
  "events": {
    "emit": ["message.created", "message.updated"],
    "listen": ["friend.deleted"]
  },
  "access": [
    {
      "product_id": "yumeFriend",
      "permission": "read"
    }
  ]
}
```

- `entities` 只列本模块数据；本机表和不上同步的表不列。
- `sync=true` 的实体参与同步。
- `assets=true` 表示实体引用附件。
- `columns` 是可执行表结构，使用 SQLite 类型 `TEXT` / `INTEGER` / `REAL` / `BLOB`；`key` 中的列必须存在。
- `migrations` 按 `version` 递增执行，每个 `sql` 项是一条语句。
- `module_registry.schema_version` 记录已执行的最高迁移版本。
- `access` 是允许访问的上限，实际访问仍需授权。
- `access` 只约束其他产品；本产品内调用不受此限制。
- `5.数据模型` 是逻辑模型，清单 `columns` 是执行结构，两者必须一致。
- 未知字段保留，不解释。

## 5. 授权

沿用 `POST /peers/{peer_id}/grant`：

```json
{
  "module_id": "memory",
  "resource_id": null,
  "permission": "read"
}
```

- `resource_id=null` 表示整个模块；否则按 `friend_id` 解释。
- 权限只有 `read` / `write`，`write` 包含 `read`。
- 无授权一律拒绝。
- 授权不能超过模块清单 `access` 的上限。
- 撤销后立即拒绝新请求。

## 6. 读写与能力调用

本机读写保持 `POST /read`、`POST /write`。

- `filter` 只做字段等值匹配。
- 带 `created_at` 的表默认按 `created_at` 升序，再按主键升序；其他表按主键升序。
- 分页使用 `cursor` + `limit`，游标不透明。
- 删除写入删除记录。

跨设备能力调用：

```json
POST /peer/v1/call
{
  "module_id": "chat",
  "capability": "chat.send",
  "input": {}
}
```

返回 `{ "output": {} }`。能力必须在清单中声明且有授权。

## 7. 事件

```json
{
  "id": "uuid",
  "type": "message.created",
  "source_module": "chat",
  "friend_id": "uuid",
  "payload": {},
  "created_at": "2026-11-22T10:00:00Z",
  "expires_at": null
}
```

- yumeCore 事件：`module.changed`、`sync.status`、`peer.found`、`sync.conflict`。
- 产品事件由模块声明。
- 事件只追加，不修改。
- 跨设备事件通过 `event` 模块同步。

## 8. 同步

局域网与服务器使用同一套请求体。

拉取：

```json
{
  "device_id": "uuid",
  "cursor": "opaque",
  "module_ids": ["chat", "memory", "schedule", "life"]
}
```

返回：

```json
{
  "cursor": "opaque",
  "changes": [],
  "tombstones": [],
  "has_more": false
}
```

变更：

```json
{
  "module_id": "chat",
  "entity_type": "messages",
  "entity_id": "uuid",
  "updated_at": "2026-11-22T10:00:00Z",
  "data": {}
}
```

删除：

```json
{
  "module_id": "chat",
  "entity_type": "messages",
  "entity_id": "uuid",
  "deleted_at": "2026-11-22T10:00:00Z"
}
```

推送返回 `{ "cursor": "opaque" }`。

规则：

- 只同步清单声明且已授权的数据。
- 不传数据库文件。
- `entity_id` 在单主键时为键值；复合主键时为键值 JSON 数组字符串。
- 本地 `updated_at` 较新则保留本地；较旧则应用远端。
- 时间相同但数据不同：写入 `sync_conflicts`，保留本地，不自动覆盖。
- 删除记录按时间参与同一比较。

局域网对端接口：

- `GET /peer/v1/info`
- `GET /peer/v1/grants`
- `POST /peer/v1/pull`
- `POST /peer/v1/push`
- `GET /peer/v1/assets`
- `GET /peer/v1/assets/{sha256}`
- `POST /peer/v1/assets/{sha256}`

附件上传带查询参数 `asset_id` 与 `mime`，用于在接收端保留同步记录引用的 asset ID。

服务器接口：

- `POST /server-sync/v1/pull`
- `POST /server-sync/v1/push`
- `GET /server-sync/v1/assets`
- `GET /server-sync/v1/assets/{sha256}`
- `POST /server-sync/v1/assets/{sha256}`

## 9. 附件

- 附件按 SHA-256 去重和传输。
- 数据库只存文件信息和引用关系。
- 附件上传和下载按引用它的模块授权校验，无授权拒绝。
- 对端只能看到、下载或上传其已授权模块引用到的附件；上传必须带 `asset_id`。
- `voices`、`embeddings`、`module_registry` 只存本机，不参与同步。
- 语音音频不进入服务器同步。

## 10. 兼容与拒绝

- 协议版本不一致：拒绝配对、能力调用和同步。
- 未知事件、未知字段：忽略。
- 未知模块或实体：跳过，不报业务错误。
- 无 token、无授权、越权访问：拒绝。

## 11. 本版不做

- 不做公网自动发现。
- 不做多跳转发。
- 不做能力调用流式传输。
- 不做自动冲突合并。
