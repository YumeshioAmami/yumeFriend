# yumeFriend 架构设计

本项目采用 **模块化单体 + 插件式模块 + 事件驱动 + 嵌入式 yumeCore 运行时** 的多产品架构。每个产品独立运行，内部按模块拆分，产品之间通过统一协议协作。

## 1. 分层

```text
产品壳
  yumeFriend 桌面（Electron）
  yumeFriend 手机（Android）
  yumeGame / yumeStudy / yumeTools
        ↓
功能模块
  聊天 / 日程 / 语音 / 生活线 / 工具 ...
        ↓
yumeCore 运行时
  清单加载 / 通用读写 / 事件 / 同步 / 授权 / 发现 / 模块生命周期
        ↓
平台层
  数据库 / 文件 / 模型调用 / 调度 / 日志 / 更新
```

| 层 | 负责 |
|---|---|
| 产品壳 | 页面、窗口、主题、用户操作 |
| 功能模块 | 自己的业务、界面、数据声明、工具、任务 |
| yumeCore 运行时 | 加载模块、读写数据、发事件、同步、授权、发现 |
| 平台层 | 数据库、文件、模型调用、调度、日志、更新 |

## 2. yumeCore 是什么

yumeCore 是嵌入每个产品的运行时，不是数据仓库。

它负责：

- 读取产品清单和模块清单
- 提供通用读写接口
- 管理事件
- 执行同步规则
- 管理授权
- 发现同系列产品
- 管理模块启动和停止

yumeCore 是 Kotlin Multiplatform 运行时，无界面、无业务模块、不拥有数据。

朋友、记忆、对话、生活线都是模块，由产品清单加载；yumeCore 只提供通用读写、事件、同步、授权、发现和模块生命周期，不认识具体模块和业务。

数据本身存在数据库里，不在 yumeCore 里。

## 3. 产品与模块

每个产品 = 产品壳 + 功能模块 + 指定版本的 yumeCore。

一个产品可以有多个壳：yumeFriend 电脑用 Electron + React + Python，手机用 Kotlin + Compose；两端共用同一套 yumeCore、模块清单和协议。

每个功能 = 一个模块。模块清单写清楚：

- 自己的数据
- 提供的能力
- 发出和监听的事件
- 哪些数据要同步
- 哪些产品能访问

模块清单的具体格式，写在《生态协作协议》里。

产品内部怎么设计，yumeCore 不管。产品只需把要共享的部分映射成 yumeCore 的数据格式。

## 4. 依赖规则

- 上层依赖下层，不能反向依赖。
- 模块只能依赖 yumeCore 和平台层，不能依赖另一个模块。
- 产品不能直接读别的产品的数据库。
- yumeCore 里不出现具体产品名和具体功能名。
- 跨产品交流只走统一接口或事件。
- yumeCore 是独立仓库、独立版本，产品按版本引入，不直接改它的源码。
- 主题属于产品壳，只改样式变量，不进 yumeCore，不改数据结构和模块接口。

## 5. 数据边界

- **跨产品数据**：朋友、记忆、对话、日程、生活线等，由对应模块管理。
- **产品数据**：学习资料、工具配置、产品自己的业务数据，归各自产品。
- **文件区**：图片、语音、模型等大文件，数据库只存路径和元数据。
- 主题配置存 settings，不单独建表。
- 不同产品可以使用不同数据库；同步走逻辑数据，不传数据库文件。

## 6. 同步

同步是 yumeCore 的运行时能力，支持局域网直连和服务器同步。

设备按模块清单和授权交换逻辑数据、事件和附件，不传数据库文件。

发现、peer、授权和同步状态由 yumeCore 内部表保存；电脑端由 JVM host 暴露局域网与服务器端点，Android 由应用内嵌 peer HTTP 服务暴露同一逻辑。发现优先使用 mDNS，手动地址只作为调试和回退入口。

## 7. 生态协作

产品之间有三种关系：

- 能力调用
- 事件通知
- 数据共享

产品发现、授权、能力登记、数据范围，都由 yumeCore 提供。具体规则见《生态协作协议》。
