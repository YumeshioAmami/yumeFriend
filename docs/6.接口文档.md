# yumeFriend 接口文档

## 1. 通用约定

- yumeCore 本机接口：`http://127.0.0.1:{core_port}/core/v1`
- 电脑端产品接口：`http://127.0.0.1:{port}/api/v1`
- 手机端接口：Kotlin 接口，不走 HTTP
- 服务器同步接口：`https://{server}/server-sync/v1`
- 请求和响应使用 JSON；文件上传用 `multipart/form-data`。
- ID 使用 UUID 字符串。
- 时间使用 UTC ISO8601；日程的 `date_local`、`time_local` 使用本地值。
- 数据库里带 `_json` 的字段，接口返回解析后的对象或数组。
- 对象字段与 `5.数据模型` 一致；`module_id` 见 `5.数据模型` 的 `1.1 模块 ID`。
- 列表返回 `{items, next_cursor}`；分页参数 `cursor`、`limit`。
- 电脑端产品接口不需要 token；对端接口使用 `X-YF-Peer-Token`；服务器同步使用 `X-YF-Server-Token`。

错误格式：

```json
{
  "error": {
    "code": "not_found",
    "message": "资源不存在"
  }
}
```

## 2. yumeCore 接口

yumeCore 是通用运行时，不提供业务接口。实体名、表、同步范围由模块清单定义。

### 2.1 本机 HTTP / WebSocket

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/modules` | 模块清单 |
| POST | `/read` | 通用读 |
| POST | `/write` | 通用写 |
| GET | `/events` | 事件列表，可按 `after` 拉取 |
| WS | `/ws` | 事件推送 |
| GET | `/devices` | 本机和已知设备 |

| POST | `/sync/run` | 局域网或服务器同步 |
| GET | `/sync/conflicts` | 同步冲突 |

通用读：

```json
{
  "module_id": "chat",
  "entity": "messages",
  "filter": { "friend_id": "uuid" },
  "cursor": null,
  "limit": 50
}
```

```json
{
  "module_id": "chat",
  "entity": "messages",
  "op": "create",
  "data": {}
}
```

`op` 取 `create` / `update` / `delete`。

配对：

```json
{
  "device_id": "uuid"
}
```

返回：

```json
{
  "peer_id": "uuid",
  "pair_secret": "secret"
}
```

能力调用：

```json
{
  "peer_id": "uuid",
  "module_id": "chat",
  "capability": "chat.send",
  "input": {}
}
```

返回 `{ "output": {} }`。

模块授权：

```json
{
  "module_id": "memory",
  "resource_id": null,
  "permission": "read"
}
```

同步：

```json
{
  "channel": "lan",
  "peer_id": "uuid",
  "direction": "both"
}
```

`channel` 取 `lan` / `server`；`direction` 取 `pull` / `push` / `both`。

yumeCore WebSocket 事件：`module.changed`、`sync.status`、`peer.found`、`sync.conflict`。

### 3.3 聊天

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/friends/{friend_id}/messages` | 消息历史 |
| POST | `/friends/{friend_id}/messages` | 发送用户消息并开始回复 |
| GET | `/messages/{message_id}` | 单条消息 |
| DELETE | `/messages/{message_id}` | 删除消息 |
| POST | `/messages/{message_id}/retry` | 重新生成这条回复 |
| POST | `/messages/{message_id}/stop` | 停止生成 |
| GET | `/messages/{message_id}/stream` | SSE 流 |
| POST | `/messages/{message_id}/voice` | 重新合成语音 |

`POST /messages/{message_id}/stop` 取消当前生成，保留已生成正文并标记 `partial`。

`GET /friends/{friend_id}/messages` 默认返回最近 200 条，按时间升序；传 `cursor` 返回该消息之前的一页，`next_cursor` 用于继续加载更早历史。

`POST /messages/{message_id}/retry` 为同一条用户消息新建一条助手回复并开始流式生成；原消息保留。

发送消息：

```json
{
  "content": "今天好累",
  "asset_ids": [],
  "reply": true
}
```

返回：

```json
{
  "user_message": {},
  "reply_message": {}
}
```

助手消息额外返回 `mood` 和 `segments`：

```json
{
  "mood": "心动",
  "segments": [
    {"bubble": 0, "text": "我很开心呀，谢谢梦汐送的礼物！喵呜~", "mood": "高兴"},
    {"bubble": 0, "text": "不过。。可惜我不能在现实中收到。。。", "mood": "伤心"},
    {"bubble": 1, "text": "嘛，不过我还是很开心哒~", "mood": "心动"}
  ]
}
```

情绪分类在完整回复生成后执行，不阻塞正文流式输出；普通聊天只使用 `segments` 的 `bubble` 分组，不使用 `mood`。

消息对象同时返回 `sources` 和 `tool_calls`（由 `sources_json` / `tool_calls_json` 解析），供聊天页显示来源和工具记录。

消息对象返回 `voice_asset_ids`，按 `message_assets.position` 排序。助手消息按气泡逐段合成，一个气泡一个音频；`POST /messages/{message_id}/voice` 重新合成并替换该消息的语音附件，返回 `{message}`。

## 4. 手机端产品接口

Compose ↔ Kotlin 业务 / yumeCore。Kotlin 接口，不走 HTTP。

```kotlin
interface MobileApi {
    fun friends(): List<Friend> // 含 unread_count
    fun messages(friendId: String, cursor: String?): MessagePage
    fun sendMessage(friendId: String, text: String, assetIds: List<String>): SendResult
    fun sendMessageStream(friendId: String, text: String, assetIds: List<String>): Flow<ChatEvent>
    fun stopMessage(messageId: String)
    fun retryMessage(messageId: String): Flow<ChatEvent>
    fun markRead(friendId: String)

    fun memories(friendId: String): List<Memory>
    fun addMemory(friendId: String, req: MemoryDraft): Memory
    fun updateMemory(memoryId: String, req: MemoryPatch): Memory
    fun deleteMemory(memoryId: String)
    fun recallMemories(friendId: String, query: String): List<Memory>

    fun schedules(friendId: String): List<Schedule>
    fun createSchedule(friendId: String, req: ScheduleDraft): Schedule
    fun updateSchedule(scheduleId: String, req: SchedulePatch): Schedule
    fun settleSchedule(scheduleId: String, reason: String): Schedule

    fun documents(friendId: String): List<Document>
    fun searchDocuments(friendId: String, query: String): List<DocumentHit>

    fun synthesize(text: String, voiceId: String?): Asset
    fun transcribe(assetId: String): Transcript
    fun voices(): List<Voice>
    fun addVoice(name: String, engineVoice: String, locale: String): Voice
    fun deleteVoice(voiceId: String)
    fun bindVoice(friendId: String, voiceId: String?, replyEnabled: Boolean)

    fun settings(scope: String): List<Setting>
    fun theme(): Theme
    fun setTheme(theme: Theme)
}
```

请求和响应对象与 `5.数据模型` 一致。手机端首期只提供聊天、记忆、日程、语音、知识库、主题。

`messages` 默认返回最近 200 条，`cursor` 继续加载更早消息；`stopMessage` 保留已生成正文并标记 `partial`；`retryMessage` 为原用户消息新建一条助手回复；`markRead` 写入该朋友未读消息的 `read_at`。

Android 音色存 `voice` 模块，`provider` 为 `system`，`config_json` 保存 `{"engine_voice":"...","locale":"..."}`；`bindVoice` 写朋友的 `voice_id` 和 `voice_reply_enabled`。

手机回复完成后用同一模型从最近对话提取最多 3 条长期记忆，跳过重复内容；每次聊天按当前用户消息做文本回忆，命中记忆和固定 / 高重要度记忆注入上下文。

Android 功能开关存 `feature_memory_enabled`、`feature_schedule_enabled`、`feature_voice_enabled`、`feature_knowledge_enabled`，默认 `true`。头像通过本机附件通道保存，朋友只存 `avatar_asset_id`。

## 5. 流式与事件

聊天流：

```text
event: start
data: {"message": {}}

event: delta
data: {"text": "今"}

event: end
data: {"message": {"mood": "心动", "segments": [{"bubble": 0, "text": "今天也辛苦了。", "mood": "高兴"}]}}

event: error
data: {"code": "model_error", "message": "模型调用失败"}
```

事件格式：

```json
{
  "id": "event-uuid",
  "type": "message.created",
  "payload": {},
  "created_at": "2026-11-21T10:00:00Z"
}
```

## 6. 错误码

| 错误码 | 说明 |
|---|---|
| `bad_request` | 请求参数错误 |
| `validation_error` | 字段校验失败 |
| `not_found` | 资源不存在 |
| `conflict` | 数据冲突 |
| `sync_error` | 同步失败 |
| `model_error` | 模型调用失败 |
| `internal_error` | 内部错误 |
